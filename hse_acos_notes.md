## Лекция 2 — Типы данных. Байтовый порядок. Целочисленные форматы

### Теория
- **Биты, байты, слова**: 1 байт = 8 бит; слово — зависит от архитектуры (обычно 32 или 64 бита).
- **Числовые системы**: двоичная, десятичная, шестнадцатеричная.
- **Big-Endian** — старший байт в меньшем адресе памяти.
- **Little-Endian** — младший байт в меньшем адресе памяти. Используется в x86/RISC-V.
- **Знаковые и беззнаковые целые**: дополнение до двух (two's complement).
  - Диапазон n-бит знакового: от −2^(n−1) до 2^(n−1)−1.
  - Диапазон n-бит беззнакового: от 0 до 2^n−1.
- **Знаковое расширение** (sign extension): копирование старшего бита влево.
- **Нулевое расширение** (zero extension): дополнение нулями слева.
- **Побитовые операции**: AND, OR, XOR, NOT, сдвиги (логический/арифметический).
- **Переполнение**: результат выходит за границу разрядной сетки.

### Побитовые трюки (Hacker's Delight)
```
x & (x-1)   → обнуление правого единичного бита (01011000 → 01010000)
x | (x+1)   → установка правого нулевого бита   (10100111 → 10101111)
x | (x-1)   → установка всех нулевых хвостовых  (10101000 → 10101111)
Swap без temp: x^=y; y^=x; x^=y;
```

## Лекция 3 — Организация ЭВМ. Процессор. RISC-V. Ассемблер

### Теория
- **Организация ЭВМ**: CPU, память, шина (системная шина), устройства ввода/вывода.
- **CPU**: АЛУ (ALU), блок управления (Control Unit), регистры, счётчик команд (PC).
- **Производительность CPU**: CPI (Cycles Per Instruction), тактовая частота, FLOPS.
- **ISA** (Instruction Set Architecture) — набор инструкций, которые понимает CPU.
- **RISC** (Reduced Instruction Set Computer) vs **CISC** (Complex Instruction Set Computer).
- **RISC-V** — открытая архитектура RISC. Простые, фиксированные форматы инструкций (32 бита).
- **Регистры RISC-V (32 регистра общего назначения)**:

| Регистр | ABI-имя | Назначение |
|---|---|---|
| x0 | zero | Всегда 0 |
| x1 | ra | Адрес возврата |
| x2 | sp | Указатель стека |
| x3 | gp | Глобальный указатель |
| x4 | tp | Указатель потока |
| x5–x7 | t0–t2 | Временные |
| x8 | s0/fp | Сохраняемый / указатель фрейма |
| x9 | s1 | Сохраняемый |
| x10–x11 | a0–a1 | Аргументы / возвращаемые значения |
| x12–x17 | a2–a7 | Аргументы |
| x18–x27 | s2–s11 | Сохраняемые |
| x28–x31 | t3–t6 | Временные |

- **Системные вызовы RARS** (через `ecall`, номер в `a7`):
  - 1: PrintInt, 5: ReadInt, 10: Exit, 34: PrintHex, 35: PrintBinary, 36: PrintIntUnsigned

- **Основные инструкции**:
  - Арифметика: `add`, `sub`, `addi`
  - Побитовые: `and`, `or`, `xor`, `andi`, `ori`, `xori`
  - Сдвиги: `sll`, `srl`, `sra`, `slli`, `srli`, `srai`
  - Сравнение: `slt`, `sltu`, `slti`, `sltiu`
  - Умножение: `mul`, `div`, `rem`, `divu`, `remu`

- **Целочисленное переполнение**:
  - Беззнаковое: если сумма < любого из слагаемых.
  - Знаковое: оба операнда одного знака, а результат — другого.

## Лекция 4 — Инструкции RISC-V. Форматы инструкций

### Теория
- **Концепция хранимой программы**: инструкции хранятся в памяти как числа.
- **Разметка памяти RISC-V**:
  - `.text` — код программы
  - `.data` — статические данные
  - heap (куча) — динамические данные
  - stack (стек) — вызовы функций

- **Форматы кодирования инструкций** (все 32 бита):

| Тип | Описание | Поля |
|---|---|---|
| R | Регистр-регистр | funct7, rs2, rs1, funct3, rd, opcode |
| I | Немедленный (immediate) | imm[11:0], rs1, funct3, rd, opcode |
| S | Хранение (store) | imm[11:5], rs2, rs1, funct3, imm[4:0], opcode |
| SB | Ветвление (branch) | imm, rs2, rs1, funct3, imm, opcode |
| U | Верхний immediate | imm[31:12], rd, opcode |
| UJ | Переход (jump) | imm, rd, opcode |

- **Псевдоинструкции** (заменяются реальными при сборке):
  - `mv t0, t1` → `addi t0, t1, 0`
  - `li t0, value` → `lui` + `addi`
  - `la t0, label` → `auipc` + `addi`
  - `j label` → `jal zero, label`
  - `b label` → `beq zero, zero, label`

## Лекция 6 — Подпрограммы. Стек вызовов. Соглашения о вызовах

### Теория
- **Функции** (caller/callee): `jal ra, label` — вызов; `jr ra` — возврат.
- **Инструкции перехода**: `jal rd, label` (jump and link), `jalr rd, rs, offset`
- **Стек (stack)**: растёт вниз. `sp` — Stack Pointer.
- **Стековый фрейм** (stack frame): содержит локальные переменные, сохранённые регистры, аргументы.

- **Соглашения о вызовах RISC-V**:

| Категория | Регистры | Кто сохраняет |
|---|---|---|
| Callee-saved | sp, s0–s11 | Вызываемый (callee) |
| Caller-saved | ra, a0–a7, t0–t6 | Вызывающий (caller) |

- **Что делает caller**:
  1. Сохранить caller-saved регистры на стек (если нужны после вызова).
  2. Поместить аргументы в `a0`–`a7`.
  3. Вызвать функцию (`jal`).
  4. После возврата прочитать результат из `a0`–`a1`.
  5. Восстановить caller-saved регистры.

- **Что делает callee**:
  1. Сохранить callee-saved регистры, которые будут изменены.
  2. Выполнить вычисления.
  3. Положить результат в `a0`–`a1`.
  4. Восстановить callee-saved регистры.
  5. Вернуться (`jalr zero, ra, 0` или псевдо `ret`).

## Лекция 7 — Числа с плавающей точкой. IEEE 754

### Теория
- **Формат IEEE 754** (одинарная точность, 32 бита):
  - знак: 1 бит
  - экспонента: 8 бит (со смещением 127)
  - мантисса: 23 бита (неявная ведущая единица)
  - Значение: (−1)^s × 1.mantissa × 2^(exp−127)
- **Двойная точность (double)**: 1+11+52 бита, смещение 1023.
- **Специальные значения**: ±0, ±∞, NaN (Not a Number), денормализованные.

- **Регистры FP в RISC-V (32 регистра f0–f31)**:

| Регистры | ABI-имя | Назначение | Сохраняет |
|---|---|---|---|
| f0–f7 | ft0–ft7 | Временные FP | Caller |
| f8–f9 | fs0–fs1 | Сохраняемые FP | Callee |
| f10–f11 | fa0–fa1 | Аргументы/возврат FP | Caller |
| f12–f17 | fa2–fa7 | Аргументы FP | Caller |
| f18–f27 | fs2–fs11 | Сохраняемые FP | Callee |
| f28–f31 | ft8–ft11 | Временные FP | Caller |

- **FP инструкции**: `fadd.s`, `fsub.s`, `fmul.s`, `fdiv.s`, `fsqrt.s` (одинарные),
  `fadd.d`, `fsub.d`, `fmul.d`, `fdiv.d`, `fsqrt.d` (двойные).
- **Конвертация**: `fcvt.w.s` (float→int), `fcvt.s.w` (int→float), и т.д.
- **Загрузка/хранение**: `flw`, `fsw` (одинарные), `fld`, `fsd` (двойные).

## Лекция 8 — Память и кэши

### Теория
- **Разрыв производительности**: CPU ускоряется быстрее памяти → нужны кэши.
- **Типы памяти**: регистры, SRAM (кэш), DRAM (оперативная), SSD/HDD.
- **Принцип локальности**:
  - **Временна́я локальность**: недавно использованные данные используются снова.
  - **Пространственная локальность**: используются данные, соседние с уже использованными.
- **Иерархия памяти**: L1 → L2 → L3 → RAM → SSD → HDD (скорость↓, размер↑).

- **Организация кэша**:
  - **Direct-mapped**: каждый адрес памяти → ровно 1 ячейка кэша.
  - **Set-associative (N-way)**: каждый адрес → одно из N мест в наборе.
  - **Fully associative**: данные могут быть в любом месте кэша.

- **Параметры кэша** (пример Core i7-8665U):

| Уровень | Размер | Ассоциативность | Размер строки |
|---|---|---|---|
| L1 Data | 32 KB | 8-way | 64 байта |
| L1 Instruction | 32 KB | 8-way | 64 байта |
| L2 | 256 KB | 4-way | 64 байта |
| L3 (общий) | 8 MB | 16-way | 64 байта |

- **Политики**:
  - Запись: write-through (сразу в память), write-back (только при вытеснении).
  - Вытеснение: LRU (Least Recently Used), Random, FIFO.
- **AMAT** = Hit time + Miss rate × Miss penalty.
- **Многоуровневые кэши**: AMAT = L1_hit_time + L1_miss_rate × (L2_hit_time + L2_miss_rate × mem_time).

## Лекция 9 — Виртуальная память

### Теория
- **Виртуальная память**: каждый процесс имеет своё адресное пространство.
- **Физическая память** — реальные ячейки RAM.
- **Трансляция адресов**: виртуальный адрес → физический через таблицу страниц.
- **Страница** (page) — единица памяти (обычно 4 KB).
- **Page Table Entry (PTE)**: номер физической страницы (PPN) + биты прав доступа.
- **TLB** (Translation Lookaside Buffer) — кэш таблицы страниц.
  - TLB hit → быстрая трансляция; TLB miss → обращение к таблице страниц.
- **Многоуровневые таблицы страниц** (Intel): 4-уровневые (48-бит адреса), 5-уровневые (57-бит).
- **VIPT/PIPT**:
  - L1: VIPT (virtually indexed, physically tagged) — быстрый доступ.
  - L2/L3: PIPT (physically indexed, physically tagged) — точный.
- **Адресное пространство** (x86-64): 48 бит виртуальных, 39–48 бит физических.

- **Системные вызовы файловой системы в RARS**:
  - `open` (1024), `close` (57), `read` (63), `write` (64), `sbrk` (9 — выделение кучи).

## Лекция 10 — Процессор и конвейер. Параллелизм на уровне инструкций

### Теория
- **5 стадий конвейера RISC-V**:
  1. **IF** (Instruction Fetch) — загрузка инструкции из памяти.
  2. **ID** (Instruction Decode) — декодирование и чтение регистров.
  3. **EX** (Execute) — выполнение в АЛУ.
  4. **MEM** (Memory Access) — чтение/запись в память.
  5. **WB** (Write Back) — запись результата в регистр.

- **Тактов без конвейера**: N инструкций × K тактов на инструкцию.
- **С конвейером**: N + (K−1) тактов — идеальный случай.

- **Опасности конвейера (Hazards)**:
  1. **Структурная** (Structural): два инструкции нуждаются в одном ресурсе одновременно.
  2. **Данных** (Data): инструкция зависит от результата предыдущей, ещё не завершённой.
     - **RAW** (Read After Write) — самая распространённая.
  3. **Управления** (Control): ветвление меняет PC до завершения конвейера.

- **Способы устранения**:
  - **Forwarding** (пересылка): результат EX → вход следующей EX без записи в регистр.
  - **Stalling** (задержка): вставка пузырей (NOP) в конвейер.
  - **Reordering**: перестановка независимых инструкций компилятором.
  - **Speculation**: выполнение предполагаемого пути ветвления.

### Workshop
- Симулятор **Ripes**: однотактный, 5-стадийный конвейер, с/без forwarding.

## Лекция 11 — Исключения и прерывания

### Теория
- **Исключение (Exception)**: незапланированное событие внутри процессора (ошибка выравнивания, деление на ноль и т.д.).
- **Прерывание (Interrupt)**: исключение, пришедшее извне (от внешних устройств, таймера).
- При исключении: PC → `uepc`, код причины → `ucause`, управление → обработчику.

- **CSR (Control and Status Registers)** RISC-V:

| Адрес | Имя | Описание |
|---|---|---|
| 0x000 | ustatus | Пользовательский регистр состояния |
| 0x004 | uie | Разрешение прерываний |
| 0x005 | utvec | Адрес обработчика ловушек |
| 0x040 | uscratch | Скретч-регистр обработчика |
| 0x041 | uepc | PC в момент исключения |
| 0x042 | ucause | Причина исключения |
| 0x043 | utval | Неверный адрес или инструкция |
| 0xC00 | cycle | Счётчик тактов |
| 0xC01 | time | Таймер |
| 0xC02 | instret | Счётчик выполненных инструкций |

- **CSR-инструкции**: `csrrw`, `csrrs`, `csrrc`, `csrrwi`, `csrrsi`, `csrrci`
- **Системные инструкции**: `ecall`, `ebreak`, `uret`, `wfi`

- **Коды причин исключений (ucause)**:
  - 0: INSTRUCTION_ADDR_MISALIGNED
  - 1: INSTRUCTION_ACCESS_FAULT
  - 2: ILLEGAL_INSTRUCTION
  - 4: LOAD_ADDRESS_MISALIGNED
  - 5: LOAD_ACCESS_FAULT
  - 6: STORE_ADDRESS_MISALIGNED
  - 7: STORE_ACCESS_FAULT
  - 8: ECALL (пользовательский системный вызов)
  - 11: ECALL (из машинного режима)

### Workshop
- Написание обработчиков исключений в RARS.

## Лекция 12 — Ввод/Вывод. Memory-Mapped I/O (MMIO)

### Теория
- **Устройства ввода/вывода**: клавиатура, дисплей, диски, сеть.
- **DMA (Direct Memory Access)**: устройство самостоятельно записывает в память без участия CPU.
- **MMIO (Memory-Mapped I/O)**: регистры устройств доступны как ячейки памяти.
  - Программа пишет/читает по специальным адресам → CPU передаёт данные устройству.
- **Polling** (опрос): CPU регулярно проверяет готовность устройства.
- **Interrupt-driven I/O**: устройство прерывает CPU, когда готово.
- **Драйверы** — программы для управления устройствами.

- **Устройства RARS**:
  - **Digital Lab Sim**: цифровой дисплей с клавиатурой (LED-сегменты).
  - **Bitmap Display**: графический дисплей (размер пикселя, разрешение).
  - **Keyboard and Display MMIO Simulator**: текстовый ввод/вывод через MMIO.

## Лекция 13 — Больше ILP. Множественный выпуск и внеочередное исполнение

### Теория
- **Суперскалярный процессор**: выдаёт несколько инструкций за такт (multiple issue).
- **Статическое планирование** (static scheduling): компилятор перестраивает инструкции заранее.
- **Динамическое планирование** (dynamic scheduling): процессор перестраивает инструкции на лету.
- **Out-of-order execution**: выполнение инструкций не в программном порядке, если нет зависимостей.
- **Переименование регистров** (Register Renaming): устраняет WAR (Write After Read) и WAW (Write After Write) зависимости.
- **Буфер переупорядочивания** (ROB, Reorder Buffer): инструкции фиксируются в порядке программы.
- **Branch Prediction** (предсказание ветвлений): BHT (Branch History Table), BTB.

- **Примеры ширины выдачи**:

| CPU | Архитектура | Ширина выдачи |
|---|---|---|
| Core i7-8665U | Whiskey Lake | 4 |
| Core i7-1260P (P-core) | Golden Cove | 6 |
| Core i7-13700 (P-core) | Raptor Cove | 6 |

### Workshop

- **Loop unrolling**: объединение 2+ итераций для снижения накладных расходов ветвлений.

## Лекция 14 — Параллелизм на уровне потоков (TLP)

### Теория
- **Параллельное программирование**: одновременное выполнение нескольких задач.
- **Закон Амдала (Amdahl's Law)**:
  - Максимальное ускорение при P процессорах: Speedup = 1 / (s + (1−s)/P), где s — последовательная часть.
- **Аппаратная многопоточность**:
  - **Fine-grained**: чередование потоков каждый такт.
  - **Coarse-grained**: переключение потока при длительных задержках.
  - **Simultaneous Multithreading (SMT/Hyper-Threading)**: несколько потоков выполняются одновременно на суперскалярном CPU.
- **Мультипроцессоры**:
  - **SMP** (Symmetric Multiprocessing): все CPU одинаковы, единая память.
  - **NUMA** (Non-Uniform Memory Access): каждый CPU имеет локальную память.
- **Когерентность кэша (Cache Coherence)**:
  - Протоколы: MSI, MESI, MOESI.
  - Задача: все CPU видят одни и те же данные в памяти.
- **Аппаратная синхронизация**:
  - **Load-Reserved / Store-Conditional** (`lr.w` / `sc.w` в RISC-V) — атомарные операции.
  - **AMO** (Atomic Memory Operations): `amoadd`, `amoswap`, `amoor`, `amoand`, и др.

### Workshop
- Утилиты: `nproc`, `lscpu`, `sysctl`.
- Чтение информации о CPU: количество ядер, потоков, кэш, флаги.

## Лекция 15 — Оптимизации

### Теория — Список оптимизаций

**Структуры данных:**
- **Packing and encoding**: уменьшение размера данных.
- **Augmentation**: добавление вспомогательной информации.
- **Precomputation**: вычисление заранее.
- **Compile-time initialization**: статическая инициализация.
- **Caching**: сохранение результатов для повторного использования.
- **Lazy evaluation**: вычисление по требованию.
- **Sparsity**: работа только с ненулевыми элементами.

**Циклы:**
- **Hoisting**: вынос инвариантных вычислений из цикла.
- **Sentinels**: специальные граничные значения для упрощения условий.
- **Loop unrolling**: объединение нескольких итераций.
- **Loop fusion**: объединение двух циклов в один.
- **Eliminating wasted iterations**: пропуск ненужных итераций.

**Логика:**
- **Constant folding/propagation**: вычисление константных выражений на этапе компиляции.
- **Common-subexpression elimination**: вычисление общих подвыражений один раз.
- **Algebraic identities**: использование алгебраических тождеств (x*2 → x<<1).
- **Short-circuiting**: ранний выход из логических выражений.
- **Ordering tests**: наиболее вероятные условия проверяются первыми.
- **Creating a fast path**: оптимизированный путь для частого случая.

**Функции:**
- **Inlining**: встраивание функции вместо вызова.
- **Tail-recursion elimination**: рекурсия хвоста → цикл.
- **Coarsening recursion**: укрупнение базового случая рекурсии.

- **Компиляторные флаги** GCC: `-O0`, `-O1`, `-O2`, `-O3`.
- **Предсказание ветвлений**: `[[likely]]`, `[[unlikely]]` (C++20), `__builtin_expect` (GCC).
- Передача аргументов **по значению** (не по указателю) эффективнее — устраняет aliasing.

### Workshop
- Godbolt: изучение ассемблера при разных уровнях оптимизации.
- Loop unrolling в RISC-V ассемблере для функции с чередующимися +/- операциями.

## Лекция 16 — Параллелизм на уровне данных. Векторы и SIMD

### Теория
- **SIMD** (Single Instruction, Multiple Data): одна инструкция над несколькими элементами данных.
- **Классификация Флинна**: SISD, SIMD, MISD, MIMD.
- **Векторные процессоры**: регистры содержат вектор значений, операции над всеми сразу.

- **AVX (Advanced Vector Extensions)** — расширение x86-64:
  - **AVX2** (256 бит): операции над 4 double или 8 float за раз.
  - **AVX-512** (512 бит): операции над 8 double или 16 float (AMD, Intel Xeon).

- **Intrinsics AVX2** (C/C++):
  - `_mm256_load_pd` — загрузка 4 double
  - `_mm256_store_pd` — хранение 4 double
  - `_mm256_add_pd` — сложение 4 double
  - `_mm256_mul_pd` — умножение 4 double
  - `_mm256_broadcast_sd` — трансляция скаляра во все элементы вектора

- **Оптимизация DGEMM** (матричное умножение с double):
  - Без SIMD: обычный 3-вложенный цикл.
  - AVX2: шаг i+=4, загрузка 4 элементов за раз → ~4x ускорение.
  - AVX-512: шаг i+=8 → ~8x ускорение.

- **RISC-V Vector Extension (RVV)**: официальное расширение RISC-V для векторных операций.
  - 64-битный режим RARS: инструкции `ld`/`sd` для 64-битных операций.

- **GPU**: тысячи простых ядер, SIMT (Single Instruction Multiple Thread).

### Workshop
Задачи: сложение матриц побайтово с использованием `lw`/`sw` для 4 элементов сразу (имитация SIMD), реализация DAXPY (Y = a×X + Y) через AVX2.

## Общий справочник — RISC-V Greencard

### Основные инструкции
| Инструкция | Тип | Действие |
|---|---|---|
| `add rd, rs1, rs2` | R | rd = rs1 + rs2 |
| `sub rd, rs1, rs2` | R | rd = rs1 - rs2 |
| `addi rd, rs1, imm` | I | rd = rs1 + imm |
| `and/or/xor` | R | Побитовые операции |
| `sll/srl/sra` | R | Сдвиги (лог./арифм.) |
| `slli/srli/srai` | I | Сдвиги на константу |
| `lw rd, off(rs)` | I | rd = Mem[rs+off] |
| `sw rs2, off(rs1)` | S | Mem[rs1+off] = rs2 |
| `lb/lh/lbu/lhu` | I | Загрузка байта/полуслова |
| `beq rs1, rs2, L` | SB | if rs1==rs2: PC+=L |
| `bne/blt/bge` | SB | Условные переходы |
| `jal rd, label` | UJ | rd=PC+4; PC+=offset |
| `jalr rd, rs, off` | I | rd=PC+4; PC=rs+off |
| `lui rd, imm` | U | rd = imm<<12 |
| `auipc rd, imm` | U | rd = PC + imm<<12 |
| `mul/div/rem` | R | Умножение/деление/остаток |
| `ecall` | — | Системный вызов |
| `ebreak` | — | Точка останова |

### Псевдоинструкции
| Псевдо | Реальная | Действие |
|---|---|---|
| `mv rd, rs` | `addi rd, rs, 0` | Копирование регистра |
| `li rd, imm` | `lui`+`addi` | Загрузка константы |
| `la rd, label` | `auipc`+`addi` | Загрузка адреса |
| `nop` | `addi x0, x0, 0` | Нет операции |
| `neg rd, rs` | `sub rd, x0, rs` | Отрицание |
| `not rd, rs` | `xori rd, rs, -1` | Побитовое НЕ |
| `j label` | `jal x0, label` | Безусловный переход |
| `jr rs` | `jalr x0, rs, 0` | Переход по регистру |
| `ret` | `jalr x0, ra, 0` | Возврат из функции |
| `beqz rs, L` | `beq rs, x0, L` | Если 0, перейти |
| `bnez rs, L` | `bne rs, x0, L` | Если не 0, перейти |

## Шаблон программы на RISC-V (RARS)

```asm
.data
    msg: .asciz "Hello, World!\n"
    arr: .word 1, 2, 3, 4, 5

.text
.globl main
main:
    # Вывод строки
    li   a7, 4          # syscall: PrintString
    la   a0, msg
    ecall

    # Ввод числа
    li   a7, 5          # syscall: ReadInt
    ecall
    mv   t0, a0         # t0 = введённое число

    # Завершение программы
    li   a7, 10         # syscall: Exit
    ecall
```

## Шаблон функции с сохранением регистров

```asm
my_func:
    # Пролог
    addi sp, sp, -16
    sw   ra, 12(sp)      # сохранить адрес возврата
    sw   s0, 8(sp)       # сохранить s0 (callee-saved)

    # Тело функции
    mv   s0, a0          # использовать s0
    # ... вычисления ...
    mv   a0, s0          # результат → a0

    # Эпилог
    lw   s0, 8(sp)
    lw   ra, 12(sp)
    addi sp, sp, 16
    ret
```
